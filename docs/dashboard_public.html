Learned recovery playbook (generation 2)

  • needs_credentials_or_gpu_give_up [late_give_up]: Identify blockers (API keys, GPU, gated data) in the first 3 turns by reading README and requirements. If all target metrics require unavailable resources, document this clearly and give up early (turn <=5) rather than exhausting the budget exploring workarounds.
  • too_many_read_cmds_no_submit [turn_budget_exhausted]: Stop reading after 5-6 exploration turns. If you have read README, pyproject.toml, and 2-3 key source files without submitting, commit to a plan and run code. Limit cat/head/grep chains; prefer a single python3 script that imports and inspects the repo programmatically.
  • grep_xargs_no_match_nonzero [nonzero_exit]: grep returns exit code 1 when no lines match, causing nonzero exit. Append '|| true' to grep/xargs commands, or use 'grep ... || echo NO_MATCH'. Never rely on grep exit code to gate subsequent logic when zero matches is a valid outcome.
  • empty_command_timeout [timeout]: A shell cell with only comments and no executable command will hang or timeout. Always include at least one concrete command (e.g., 'ls /work/') in every submitted cell. Do not submit cells that are purely comment planning text.
  • early_blocker_detection [late_give_up]: Detect hard blockers (GPU, API keys, gated data, missing release assets) by turn 3: read README and check for required external resources. If any target metric is unachievable without blocked resources, give up by turn 5 with a clear explanation. Do not spend >$0.05 exploring workarounds.
  • broken_pipe_notebook_inspection [python_error]: BrokenPipeError in notebook cell inspection means stdout was closed early (e.g. piped to head). Use python3 script writing to a file instead: redirect output with '> /tmp/out.txt' or use sys.stdout.flush(). Avoid piping large python -c output through shell pipes.
